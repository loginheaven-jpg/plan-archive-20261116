# 일정 데이터베이스와 API 운영

## 격리와 연결

`DATABASE_URL`은 일정 프로젝트 전용 MySQL DSN입니다. 서버는 `mysql2` 연결 풀을 최초 DB 요청 때 생성하고 Drizzle ORM으로 매개변수화된 질의를 실행합니다. DSN의 `ssl` JSON/true 및 `ssl-mode`/`sslmode` 옵션을 존중합니다. TLS가 지정되면 별도 설정이 없는 한 인증서 검증을 활성화합니다. DSN과 드라이버 오류의 민감한 내용은 응답·로그에 남기지 않습니다. 애플리케이션 오류 로그에는 무작위 요청 추적 번호만 있습니다.

개발 Preview와 관리형 공개 배포는 같은 DB를 사용할 수 있습니다. 테스트에서 운영 DB에 이벤트나 가상 계정을 넣지 않습니다. 기존 재정부 DB, Google Sheets, 재정 원장에는 접근하지 않습니다.

## 명시적 마이그레이션

```sh
pnpm db:migrate
```

`drizzle/0001_calendar.sql`과 `scripts/migrate.ts`가 스키마를 관리합니다. 실행 전 테이블 목록을 읽고 `plan_` 접두사 밖의 테이블이 있으면 다른 DB를 잘못 지정한 것으로 보고 중단합니다. MySQL advisory lock으로 동시 실행을 막습니다. DDL은 `CREATE TABLE IF NOT EXISTS`뿐이며 기존 테이블을 삭제·초기화하지 않습니다. MySQL DDL은 트랜잭션 원자성을 제공하지 않기 때문에 중단 후 재실행할 수 있도록 반복 가능한 추가 작업으로 구성했습니다. 설정 초기 행과 완료 이력은 같은 트랜잭션에 기록합니다. 완료된 파일의 SHA-256이 달라지면 중단하며 다음 변경은 새 마이그레이션으로 추가해야 합니다.

시작 시 마이그레이션이나 seed를 자동 실행하지 않습니다. `GET /api/health`는 연결·완료 이력·필수 테이블·설정 행이 준비되면 인증 없이 200, 미준비·연결 실패면 503을 반환합니다. DB 오류를 가짜 빈 일정 응답으로 처리하지 않습니다.

실제 새 프로젝트 DB를 읽기 전용으로 확인했을 때 테이블이 없었습니다. 승인된 추가 마이그레이션을 실행했고 두 번째 실행은 기존 데이터와 설정을 보존했습니다. 작성된 데이터는 교회 관행을 미확인으로 둔 최초 설정 1행과 마이그레이션 이력 1행뿐입니다. 일정·감사·사용자·장소 샘플은 없습니다. 실제 장소가 확인되지 않아 장소 목록은 비어 있으며 자유 입력 장소를 사용할 수 있습니다.

## 테이블

| 테이블 | 내용 |
|---|---|
| `plan_events` | 안정적인 UUID, 고유 operation ID, 최초 작성자 ID와 최초 입력, 권한·날짜·반복 종료·장소·버전·삭제 상태 색인, authoritative JSON 일정 |
| `plan_audit` | 삽입 전용 변경 이력 JSON, 대상 ID, 서버 UTC 시각. 이벤트/설정/권한 변경 모두 기록 |
| `plan_users` | 실제 검증 로그인 사용자 ID·이름·캘린더 역할·부서 권한·최근 접속시각 |
| `plan_settings` | 교회력 설정과 별도 설정 버전. 교회 설정 행 ID는 `church` |
| `plan_venues` | 관리자가 실제 확인하여 추가한 정규화 장소 ID·이름 |
| `plan_migrations` | 마이그레이션 ID·checksum·완료시각 |

JSON이 완전한 행사 원본이고 색인 열은 조회용입니다. 예외로 옮겨진 회차의 범위도 색인 범위에 반영합니다. 반복 마스터는 연도 이전에 시작했더라도 반복 종료일과 회차 기간을 고려하여 검색합니다. 날짜는 한국의 `YYYY-MM-DD`·시간은 `HH:mm`, 책임 기록 시각은 UTC ISO 문자열입니다.

감사 이력은 애플리케이션에서 INSERT만 하며 수정·삭제 API가 없습니다. DB 계정 자체의 관리자 접근까지 이 코드가 WORM 저장소처럼 차단하는 것은 아닙니다. 운영 DB 접근권한과 백업 정책은 별도로 관리하세요.

## 읽기 API

- `GET /api/bootstrap?year=YYYY`: 해당 연도 마스터, 실제 한국 오늘부터 60일의 회차(최대 500), actor, venues, settings, auth. 공개/비로그인은 공개 일정만. `public=1`은 강제 공개 모드.
- `GET /api/events/{uuid}?public=1`: 공개 세부정보와 최대 100건 이력. 공개 응답에서는 개인 provenance·내부 메모를 제외하고 과거 스냅샷·행위자·사유는 제거. 이력 제목도 현재 공개 제목으로 바꾸므로 이전 비공개 제목이 유출되지 않음.
- `GET /api/changes?public=1`: 현재 행사 열람권한으로 필터한 최근 이력, 최대 100건. 설정·사용자 감사는 일반 행사 변경 피드에 포함하지 않음.
- `GET /api/trash`: 로그인 필수. 현재 편집권한이 있는 소프트 삭제 행사만.
- `GET /api/settings`: `{settings,venues,version}`.
- `GET /api/admin/users`: 관리자만 실제 로그인 사용자 목록, 최대 2,000.
- `GET /api/calendar.ics?org=worship,mission&all=1&churchYear=1&year=YYYY`: 인증 없는 실제 공개 구독. 취소·삭제 공개 tombstone과 반복 예외를 포함. Content-Type `text/calendar; charset=utf-8`. 구독은 attachment가 아니며 `download=1`일 때만 파일 attachment 헤더를 추가.

원본 행사의 권한과 확장된 실제 회차의 권한을 모두 검사합니다. 레거시 비공개 예외의 민감한 패치를 마스터 응답에서도 가립니다. 공개 ICS는 사용자·변경사유·내부 메모를 내보내지 않습니다. 구독은 공개 일정 전용이며 Google/삼성 수신 앱의 갱신 주기는 서버가 통제하지 않습니다.

## 쓰기와 충돌

모든 쓰기는 SSO 인증, 현재 DB 권한, 정확한 Origin CSRF를 검사합니다. JSON 본문은 최대 64 KiB, 최대 25단계 중첩이며 중복 JSON 키·알 수 없는 입력 항목을 거절합니다. 허용된 열만 ORM에 전달하므로 사용자 입력을 SQL 문자열로 결합하지 않습니다.

`POST /api/events`의 `{operationId:UUID,input:EventInput}`은 operation ID 자체를 고유 행사 ID로 사용합니다. 같은 최초 작성자와 같은 canonical 최초 입력에 한해 재시도가 같은 행사를 돌려줍니다. 다른 작성자·다른 입력의 ID 재사용은 409입니다. 새 등록과 감사 기록은 같은 트랜잭션입니다.

`PATCH /api/events/{id}`는 `{version,action,input?,reason?,occurrenceDate?}`을 받습니다. 설정 mutex → 현재 사용자 → 행사 순으로 행을 잠가 동시 권한 변경과 저장을 직렬화합니다. 행사 개정번호가 다르면 409이며 자동 덮어쓰지 않습니다. 바뀐 내용이 없으면 버전·변경자·변경시각을 갱신하지 않습니다. 최초 작성자·최초 시각은 보존합니다. 실제 변경과 before/after·by·reason·changedFields 감사는 같은 트랜잭션에 기록됩니다.

취소는 사유가 필수이고 전체 취소는 모든 회차에 적용됩니다. 취소된 전체 일정의 `update`로 재개하려면 정상 상태와 이유를 명시해야 하며 감사 kind는 `uncancel`입니다. 회차 재개에도 이유가 필요하고 `uncancel-occurrence`로 기록합니다. 삭제는 물리 DELETE가 아니라 tombstone이며 `restore`가 삭제만 복구합니다. 취소와 삭제는 서로 다른 상태입니다.

한 회차 변경은 유효한 **원래 반복 날짜**만 허용합니다. title·날짜·종일/시각·장소·description·internalNote·status만 패치합니다. 완전한 EventInput을 보내도 주관부서·공개범위·참여대상·반복이 원본과 같으면 무시하고, 다르면 거절합니다. 시리즈 ID·작성 기록은 바꾸지 않으며 예외와 실제 변경자를 저장하고 시리즈 버전을 증가시킵니다. 기존 예외를 무효화하는 반복 규칙 변경은 거절합니다.

`PUT /api/settings`는 관리자만 `{settings,venues?,version?}`을 저장합니다. transaction lock으로 기존 데이터를 보호하고 선택적 version이 다르면 409입니다. venues가 생략되면 기존 장소를 보존합니다. 설정을 생략·초기화하는 작업은 없으며 행사·예외·휴지통에서 쓰는 장소 ID는 제거할 수 없습니다. 정상 이름 변경은 가능하고 실제 장소 추가는 관리자 확인 후 합니다.

`PATCH /api/admin/users`는 관리자만 `{id,role,departmentIds}`로 기존 사용자 권한을 조정합니다. 사용자 생성은 하지 않으며 마지막 관리자 해제는 409입니다. 재정부 역할과 관리자 환경변수는 기존 철회 역할을 복구하지 않습니다.

## 유효성·한도·장소 안내

실제 달력 날짜(1900–2200), 텍스트 길이, enum, 부서/요일/장소 ID 중복, 시작/종료 순서를 검사합니다. 자정을 넘는 시간은 종료일을 다음 날로 지정해야 합니다. 일반 행사 기간은 최대 366일, 반복 회차 기간은 최대 31일, 반복 종료는 최초일에서 최대 5년입니다. 마스터 조회/휴지통/장소 사용 확인은 최대 2,000건을 넘으면 명시적인 범위 오류를 반환합니다. 장소는 최대 200개입니다.

정규화 장소가 있는 입력은 실제 반복 회차를 확장하여 겹침을 확인합니다. 현재 사용자가 읽을 수 없는 원본/회차는 경고에서 제외합니다. 읽을 수 있는 충돌도 `선택 장소에 겹치는 일정이 있어요.`만 반환하고 타 행사 제목·시간은 노출하지 않습니다. 자유 입력 장소는 정규화 ID가 없으므로 자동 충돌 대상으로 사용하지 않습니다. 이는 예약 승인이나 강제 차단 기능이 아닙니다.

## 검증 범위

`tests/backend.test.ts`는 실제 도메인 권한을 가져와 입력, 위조/미승인 SSO 봉인, Preview 제한, CSRF, JSON 제한, 공개 개인정보, 개정충돌·무변경·소프트 삭제/복구·예외·중복 등록·마지막 관리자 정책을 검사합니다. 트랜잭션 경로는 메모리 query-contract mock을 사용하며 관리형 DB에 쓰지 않습니다. 실제 동시 두 DB 연결 경쟁·rollback 장애 주입은 별도 격리 MySQL에서 추가 검증할 수 있습니다. 실제 SSO 로그인과 공개 운영 배포는 별도 운영 확인 사항입니다.

# 예봄일정 · 실제 교적부 SSO 연결

## 서비스 안에서 이어지는 로그인 (2026-11-16 KST)

정상 로그인은 중간 안내창 없이 공통 로그인 화면을 바로 사용한다. 교적부의 `from=plan` 서비스 정보가 예봄일정 이름·아이콘을 표시한다. 이미 유효한 공유 세션이 있으면 일정 화면에서 사용자를 자동 인식하고 로그인 폼을 열지 않는다.

공통 로그인 시작 경로의 `next`는 일정 앱의 등록된 내부 화면만 허용한다. 현재 달력 연도·월·보기와 연간계획 연도·부서를 보존하며, 교적부 로그인이 끝나면 중간 완료 화면 없이 해당 경로로 연결한다. 외부 URL·API 경로·로그인 반복 경로는 복귀 대상으로 사용하지 않는다.

첫 체크인 결과, 포커스·화면 복귀와 BFCache 복원 때 사용자 상태를 자동 갱신한다. 빠른 앱 전환을 60초 동안 무시하지 않으며 확인 중 들어온 복귀 요청도 이어서 처리한다. 달력·연간계획·설정 화면 모두 변경을 반영하고 작성 중인 입력은 보존한다. 미저장 입력이 있는 상태에서 재인증이 필요할 때만 별도 탭을 사용해 원래 입력을 유지하며, 돌아오면 수동 확인 없이 갱신한다.

서버 검증·승인/프로필 조건·일정 담당 권한·CSRF 보호는 유지한다. 명시적인 `/share` 공개 조회는 사용자 연결과 체크인을 수행하지 않는다. 운영 배포와 실제 계정 검증은 코드·격리 검사 결과와 구별한다.

2026-11-15 오후, 사용자가 제공한 `loginheaven-jpg/saint-record-v2` 현재 인증 모듈을 기준으로 보완했다.

## 열람과 편집

**일반 교회 일정은 로그인 없이 열람한다.** 입력·수정·취소·개인 초안 저장 등 편집 작업에만 기존 교적부 로그인과 일정 담당 권한을 요구한다. 새 일반 일정과 연간 행은 전체공개가 기본이다. 기존 명시적 제한 일정·개인 초안·내부 메모·개인정보를 자동 외부 공개하지 않는다.

새 Google 로그인이나 별도 간소 비밀번호 체계를 만들지 않는다. 교적부의 기존 이메일/전화번호·비밀번호 로그인 및 로그인 유지 세션을 사용한다. 비밀번호를 일정 앱에 입력하거나 저장하지 않으며, 교적부에 이미 유효하게 로그인한 경우 재입력을 요구하지 않는다.

## 별도 봉인키 복사가 필요하지 않다

새 서버 인증은 고정된 **https://saint.yebom.org/api/auth/session**에 필요한 `saint_record_session` 쿠키 하나만 전달한다. 교적부가 자신의 실제 키로 봉인을 검증하고 최신 DB와 세션 버전·회수·승인 상태를 대조한다. 일정 앱은 공식 HTTPS 응답의 승인된 사용자 ID·이름만 사용한다. 재정/교적부 관리자 역할을 일정 관리자 권한으로 자동 승격하지 않는다.

**새 인증 경로에는 `YEBOM_SSO_SECRET`이 필요하지 않다.** 예전처럼 교적부의 `SESSION_SECRET`을 일정 앱으로 복사하거나 임의 난수를 생성할 필요가 없다. 기존 값이 남아 있어도 이 경로에서 인증에 사용하지 않는다. 소스에 남은 기존 봉인 검증 함수는 격리된 이전 호환 검사 용도일 뿐 실제 인증의 대체 경로가 아니다. 기본키·개발 사용자·오프라인 인증 우회도 없다.

| 설정 | 의미 |
|---|---|
| `APP_PUBLIC_ORIGIN` | 실제 HTTPS 일정 서비스 origin. 현재 `https://plan.yebom.org`; 경로·쿼리·별도 포트·사용자정보를 허용하지 않는다. |
| `YEBOM_CALENDAR_ADMIN_IDS` | 운영자가 승인한 최초 실제 교적부 사용자 ID 목록. 임의 난수가 아니라 실제 ID이며 기존 역할을 자동 재부여하지 않는다. |
| `APP_ALLOWED_ORIGINS` | 필요할 때만 명시적으로 허용한 정확한 추가 HTTPS origin. |

교적부 운영 환경의 `COOKIE_DOMAIN=.yebom.org` 설정은 여전히 필요하다. 교적부가 호스트 전용 쿠키만 발급하면 브라우저가 plan.yebom.org에 전달하지 못한다. 일정 앱의 임의 설정으로 이 브라우저 경계를 우회하지 않는다. 교적부 비밀값·쿠키·실제 사용자 ID를 채팅이나 공개 Git에 넣지 않는다.

## 공식 체크인과 로그인 유지

교적부의 공식 확인 경로는 계정 삭제·승인 취소·모든 기기 로그아웃의 세션 버전을 재확인하고 최신 이름·권한 정보를 돌려준다. 서버 인증은 요청마다 확인하며 요청 사이 인증 결과를 캐시하지 않는다. 같은 Request 객체에서 중복 확인만 줄인다. 인증 서버 장애에는 쓰기를 허용하지 않으며 과거 봉인 결과로 대신 인증하지 않는다. 일반 공개 열람은 비로그인 상태로 계속한다.

브라우저는 같은 출처 `/api/auth/checkin`을 호출한다. 서버 간 확인이므로 교적부의 브라우저 CORS 허용 목록을 넓힐 필요가 없다. 첫 접속·포커스 복귀에서 확인하고, `/share` 공개 게시판에서는 체크인하지 않는다. 공식 응답에서 안전한 도메인·경로·HttpOnly·Secure 속성을 만족하는 **교적부 세션 쿠키만** 갱신·정리 목적으로 전달한다. 금융/기도 쿠키나 전체 Cookie 헤더를 수집·전달하지 않는다.

교적부의 현재 로그인 유지 계약은 유지 선택 시 쿠키와 봉인 400일 및 하루 1회 연장, 유지 해제 시 브라우저 세션 쿠키와 12시간 봉인이다. 일정 앱이 자체 수명으로 덮어쓰거나 무제한 토큰을 만들지 않는다. 일시 서버 장애 때는 기존 쿠키를 보존한다.

## 로그인 시작과 복귀

`/api/auth/sso`는 로그인 시작 경로다. 이미 유효한 승인 로그인이 있으면 바로 일정으로 돌아간다. 없는 경우 기존 교적부 `/login?from=plan&redirect=…`으로 이동하며 복귀 주소는 고정 일정 origin의 `/api/auth/sso?callback=1`이다. 사용자 임의의 외부 복귀 주소는 사용하지 않는다.

복귀 후에도 쿠키 없음·충돌·미승인·프로필 미완료·서버 장애이면 **다시 로그인 화면으로 무한 이동하지 않는다.** 해당 이유와 고정된 안전한 다시 시도/교적부 연결을 표시한다. `.yebom.org` 외의 Manus Preview는 공유 쿠키를 받을 수 없으므로 실제 SSO 확인은 운영 도메인에서 수행한다.

상반된 같은 이름의 쿠키는 임의로 첫 값/마지막 값을 선택하지 않는다. 동일한 중복 값만 한 값으로 다루고 서로 다른 값이면 재인증 안내를 제공한다. 브라우저 쿠키·헤더·응답 본문·키를 진단 로그에 남기지 않는다.

## 권한과 로그아웃

승인된 실제 사용자만 로컬 일정 계정에 연결한다. 신규 계정은 조회자이며 실제 ID가 명시된 최초 관리자 목록에 있을 때만 최초 관리자 역할을 부여한다. 이후 `/settings`에서 실제 로그인한 사용자에게 부서 담당·관리 권한을 지정한다. 역할 철회는 환경변수로 자동 복구하지 않는다. 로그인 성공과 편집 담당 지정은 별개다.

일정 앱의 지역 로그아웃 표식은 일반 인증에서 존중하며 명시적 로그인 성공 때만 지운다. 통합 로그아웃은 기존 교적부의 `/api/auth/logout?return=…`에서 처리한다. 일정 앱이 다른 서비스의 쿠키를 임의 삭제하지 않는다. 모든 편집 API의 정확한 Origin·현재 요청 Host·Sec-Fetch-Site CSRF 보호를 유지한다.

## 운영 확인과 남은 조건

자동 검사는 별도 가상 API 응답과 격리 DB 어댑터만 사용한다. 실제 계정으로 확인하기 전에는 로그인 완료를 주장하지 않는다. 실제 확인은 ‘교적부 로그인 → 일정 복귀 → 현재 계정 인증 확인’만 수행하고 시험 행사를 운영 DB에 넣지 않는다. 계정 승인이나 Cookie Domain 설정 자체가 잘못됐다면 교적부 운영 담당자의 설정/계정 조치가 필요하며 오류 안내로 구별한다.

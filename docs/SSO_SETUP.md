# 교적부 SSO 연결

## 현재 상태

백엔드는 실제 `saint_record_session` iron-session 봉인을 검증하도록 구현되어 있습니다. 개발 당시 `YEBOM_SSO_SECRET`과 신뢰할 수 있는 운영 주소가 설정되지 않았으므로 실제 운영 로그인은 확인하지 않았습니다. 키가 없으면 공개 조회만 허용합니다. Manus 로그인 쿠키, JWT, 재정부 역할, 개발용 가상 사용자를 일정 계정으로 바꾸는 우회는 없습니다.

## 보호된 설정으로 연결하기

다음 값은 운영 담당자가 보호된 환경변수 입력 화면에서 설정합니다. 이 문서나 Git에 실제 값을 넣지 않습니다.

| 이름 | 의미 |
|---|---|
| `YEBOM_SSO_SECRET` | 교적부와 동일한 iron-session 봉인 검증키, 최소 32자. 기본값·대체키 없음 |
| `APP_PUBLIC_ORIGIN` | 확정된 앱의 HTTPS origin. 예: `https://plan.yebom.org`. `.yebom.org` 하위 도메인만 허용하며 경로·쿼리·사용자정보·별도 포트는 금지 |
| `YEBOM_CALENDAR_ADMIN_IDS` | 운영자가 명시적으로 승인한 최초 일정 관리자 교적부 사용자 ID. 쉼표로 구분. 재정부 역할은 사용하지 않음 |
| `APP_ALLOWED_ORIGINS` | 추가로 쓰기 요청을 허용할 정확한 HTTPS origin들의 쉼표 목록. Preview가 필요하면 실제 Preview origin을 등록하는 것이 가장 안전함 |

교적부 담당자는 `from=plan`과 확정된 `${APP_PUBLIC_ORIGIN}/api/auth/sso` 복귀 주소를 허용해야 합니다. 재정부의 `from=finance` 계약을 새 앱에 그대로 가장하지 않습니다. 새 도메인의 허용 목록이 현재 확인되지 않았으며 교적부 연결 작업이 필요할 수 있습니다.

## 검증과 권한

현재 iron-session v2 wire 봉인(`Fe26.2…~2`)의 형식을 확인한 뒤 `unsealData`로 MAC·암호화·유효기간을 검증합니다. `isLoggedIn === true`, `is_approved === true`, 문자열 `user_id`와 `name`, `needs_profile_completion !== true`를 모두 요구합니다. 세션 내용을 로그에 남기지 않습니다. 중복된 같은 이름의 쿠키, 변조된 봉인, 만료된 세션, 미승인·프로필 미완료 계정은 인증하지 않습니다.

실제로 검증된 로그인에서만 `plan_users`에 사용자 이름과 최근 접속시각을 갱신합니다. 최초 역할은 `viewer`입니다. 최초 로그인 ID가 명시적 관리자 목록에 있으면 그 신규 계정만 `admin`으로 초기화할 수 있습니다. 기존 계정은 환경변수에 다시 포함되어도 철회된 역할이 자동 복원되지 않습니다. 이후 관리자는 `/api/admin/users`에서 **이미 실제로 로그인한 사용자**에게 `editor`와 담당 부서 또는 `admin` 권한을 부여합니다. 마지막 관리자의 해제는 차단하고 권한 변경은 불변 감사 이력에 추가합니다.

관리자는 전체 편집, 부서 담당자는 자신에게 허용된 주관부서 편집, 조회자는 조회만 가능합니다. 교인공개는 승인된 로그인, 부서공개는 해당 부서 권한 또는 관리자만 읽습니다. 공유 모드 `public=1`은 로그인 쿠키가 있어도 공개 데이터만 반환하며 사용자 테이블을 갱신하지 않습니다. 공개 DTO는 작성자·변경자·내부 메모 키를 아예 제외합니다. 레거시 예외의 공개범위가 더 좁은 경우 마스터에 실린 비공개 패치도 가리고 실제 회차 확장 후 권한을 다시 검사합니다.

## 도메인과 리다이렉트

`/api/auth/status`와 bootstrap의 `auth`는 검증키·운영 주소의 준비 여부, 현재 요청이 정확히 운영 도메인에 있는지, 실제 교적부 로그인 URL을 알려 줍니다. 잘못된 구성 또는 Preview에서는 로그인 URL이 `null`입니다. Manus Preview 도메인은 `.yebom.org` 쿠키를 받을 수 없으므로 실제 SSO 로그인 확인 장소가 아닙니다.

`GET /api/auth/sso`는 운영 도메인에서 검증에 성공하면 `APP_PUBLIC_ORIGIN`의 고정 `/`로만 이동합니다. `redirect` 등의 사용자 입력은 사용하지 않습니다. 유효한 쿠키가 없으면 고정 `https://saint.yebom.org/login?from=plan&redirect=…` 주소로만 이동합니다. 내부 프록시 Host를 복귀 URL로 사용하지 않습니다. 준비되지 않은 SSO는 명확한 503 응답을 반환합니다.

`GET /api/auth/logout`은 검증된 운영 주소를 사용한 교적부 통합 로그아웃 링크만 반환하고 쿠키를 변경하지 않습니다. CSRF를 통과한 `POST`는 이 앱만의 호스트 전용 `yebom_plan_logged_out` 표식을 설정하여 지역 로그아웃하고 같은 통합 링크를 반환합니다. 사용자가 그 링크로 이동하면 실제 교적부가 공유 로그아웃을 처리합니다. 앱은 재정부나 교적부 쿠키를 직접 삭제하지 않습니다. 다음 명시적 SSO 로그인 성공은 이 앱의 표식만 제거합니다.

## 쓰기 요청 CSRF와 프록시 조건

모든 POST/PATCH/PUT는 `Origin`이 반드시 있어야 합니다. `null`, HTTP, 경로가 붙은 값은 거절합니다. Origin은 `APP_PUBLIC_ORIGIN` 또는 추가 허용 목록에 있어야 하며 현재 요청의 `x-forwarded-host`(없으면 `Host`, 마지막으로 request URL)로 계산한 HTTPS origin과 **정확히 같아야** 합니다. `Sec-Fetch-Site`가 있으면 `same-origin` 또는 `none`만 허용합니다. 쉼표가 섞인 전달 Host는 거절합니다.

추가 origin은 정확한 HTTPS 주소를 권장합니다. 필요한 경우 **명시적으로** `https://*.manus.computer`만 예외 패턴으로 지원합니다. 이 패턴은 실제 `.manus.computer` 경계를 검증하며 요청 Host와 정확히 일치해야 합니다. 다른 와일드카드 루트는 지원하지 않습니다. 허용된 Preview라도 검증된 교적부 쿠키를 받을 수 없으므로 일정 쓰기 인증은 실패합니다. localhost HTTP 우회는 없습니다.

운영 리버스 프록시는 `Host`/`x-forwarded-host`를 신뢰할 수 있는 외부 origin으로 덮어쓰고 임의 클라이언트 값을 제거해야 합니다. 앱 서버를 직접 외부에 노출하여 전달 헤더를 클라이언트가 조작하게 하지 마세요. 정확한 Origin 대조는 CORS 허용과 다르며 교적부 쿠키 정책을 변경하지 않습니다.

## 확인할 운영 항목

검증키의 안전한 연결, 확정 HTTPS 도메인과 인증서, 교적부의 `from=plan`·복귀 허용 목록, 공유 쿠키 전달, 최초 실제 관리자 로그인, 부서 권한 부여를 확인해야 합니다. 실제 로그인·배포 완료는 이 코드의 테스트 성공만으로 입증되지 않습니다.

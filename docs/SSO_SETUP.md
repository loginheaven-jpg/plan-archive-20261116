# 예봄일정 SSO · 같은 화면에서 로그인

## 사용자가 경험하는 흐름

일반 교회 일정은 로그인하지 않고 열람합니다. 로그인 버튼이나 일정 편집을 누르면 **현재 일정 화면 위에 로그인창만 열립니다.** 보통 로그인에서 교적부 화면으로 이동했다가 돌아오는 과정은 없습니다. 이메일 또는 전화번호와 기존 교적부 비밀번호를 입력하고, 같은 날짜·월·부서·작성 중 입력에서 계속합니다.

다른 예봄 서비스의 **유효하고 승인된 공유 세션**이 있으면 비밀번호 입력창 없이 신원을 확인합니다. 최초 접속, 다른 탭·앱에서 돌아오기, BFCache 복원과 로그인창을 열기 직전에 다시 확인합니다. `/share` 공개 게시판에는 로그인창을 강제로 띄우거나 사용자 체크인을 수행하지 않습니다.

| 확인 상태 | 로그인 신원 | 일정 편집 |
|---|---|---|
| 유효 세션·승인·필수 정보 완료 | 확인됨 | 현재 일정 담당 권한에 따름 |
| 필수 프로필 미완료 | 확인됨 | 제한 유지, 프로필 완료 후 재확인 |
| 필수 비밀번호 변경 대기 | 확인됨 | 변경 후 재확인 |
| 미승인·회수·계정 삭제·쿠키 충돌 | 인증하지 않음 | 차단 |
| 교적부 서버 장애·구형 필수 계약 | 확인할 수 없음 | 차단, 공개 열람은 계속 |

**로그인 성공과 편집 권한은 다른 조건입니다.** 조회자 계정은 로그인해도 담당 권한이 부여되기 전에는 편집할 수 없습니다. 재정부·교적부 관리자 역할을 일정 관리자 권한으로 임의 승격하지 않습니다.

## 프로필·비밀번호 완료 제한

사용자가 선택한 프로필 완료 제한을 유지합니다. 교적부의 공통 검사 항목은 **생년월일 `birth_date`, 성별 `gender`, 연락처 `phone`**입니다. 이전 화면의 `birthdate` 오기나 서버와 다른 필수 항목 목록을 같은 검사로 통일했습니다. 시스템 관리자도 임의 면제하거나 실제 프로필 값을 대신 채우지 않습니다.

유효 세션의 프로필 미완료는 “비밀번호 로그인 실패”가 아닙니다. 모달에는 신원이 확인됐다는 안내와 필요한 항목 이름만 표시합니다. 사용자가 명시적으로 교적부의 프로필·비밀번호 화면을 **새 탭**에서 열어 완료할 수 있고, 원래 일정 입력은 유지합니다. 돌아오면 자동 확인하거나 “완료 후 로그인 상태 다시 확인”을 누릅니다. 실제 값 저장과 권한 변경은 사용자가 수행합니다.

교적부는 체크인마다 현재 DB의 필수 항목·승인·비밀번호 변경 필요·세션 버전을 다시 읽습니다. 이전 쿠키의 미완료 표시를 계속 신뢰하지 않습니다. 비밀번호 변경도 현재 유효 세션과 개정번호를 검사하며 회수된 쿠키나 동시 변경이 세션을 되살리는 경로가 되어서는 안 됩니다.

## 중앙 인증과 안전한 중계

브라우저는 같은 출처 `POST /api/auth/login`으로 요청합니다. 예봄일정 서버는 **고정 `https://saint.yebom.org/api/auth/login`**에 기존 `{email,password,remember}`만 전달합니다. 비밀번호 검증과 세션 발급은 교적부만 수행합니다. 일정 서버·브라우저는 비밀번호를 데이터베이스, 파일, 진단 로그, URL, 로컬 저장소에 저장하지 않습니다. 폼의 비밀번호 값은 요청 전달 직후 지웁니다.

일정 서버는 교적부가 발급한 안전한 `saint_record_session` 쿠키를 받아 **공식 `https://saint.yebom.org/api/auth/session`**에서 다시 확인합니다. 최신 승인된 사용자 ID·이름만 신원으로 투영하며 실제 일정 역할은 일정 DB에서 확인합니다. 응답 크기·시간·쿠키 도메인·경로·HttpOnly·Secure·SameSite와 정확한 출처를 검사합니다. 외부 요청 주소를 사용자가 입력하게 하거나 인증 장애 때 로컬 봉인키로 우회하지 않습니다.

중앙 공개 세션에는 항상 `password_reset_required` 불리언이 있어야 합니다. 필수 계약이 없으면 편집 인증을 실패 처리하므로 **교적부의 v2 세션 배포를 먼저 확인한 뒤 일정 소비자를 배포**합니다. 교적부는 `auth_contract_version: 2`와 필요한 프로필 항목 이름만 추가하며 생일·전화번호 값이나 비밀번호 해시를 이 계약에 추가하지 않습니다.

인증 조회에는 교적부 쿠키 하나만 보내고 금융·기도 쿠키나 전체 브라우저 Cookie 헤더를 전달하지 않습니다. 서버 간 고정 HTTPS 통신이므로 교적부의 브라우저 CORS 범위를 넓힐 필요가 없습니다. 중앙 로그인 제한은 IP 공유 때문에 모든 사용자가 다섯 번의 시도를 나눠 쓰지 않도록 계정·식별자별 다섯 번/분 방어와 IP 과다 요청 방어를 구분합니다. 각 인스턴스의 메모리 제한이며 전 세계 분산 요청의 단일 엄격 한도를 보장한다고 주장하지 않습니다.

## 설정·호스팅

| 설정 | 의미 |
|---|---|
| `APP_PUBLIC_ORIGIN` | 현재 `https://plan.yebom.org`. 경로·쿼리·사용자정보·별도 포트 없는 운영 HTTPS origin |
| `YEBOM_CALENDAR_ADMIN_IDS` | 운영자가 승인한 실제 교적부 **user_id**. member_id나 임의 난수가 아님. 기존 역할은 환경변수로 재부여하지 않음 |
| `APP_ALLOWED_ORIGINS` | 필요한 경우만 정확하게 지정한 추가 HTTPS 출처 |
| 교적부 `COOKIE_DOMAIN` | `.yebom.org` 공유 쿠키 도메인 |

현재 일정 호스팅·독립 MySQL과 교적부 Vercel을 유지합니다. Railway로 이전하거나 운영 데이터를 복사하지 않습니다. Dockerfile·Railway 참고 선언은 이전 가능성을 위한 사용자 소스에 남길 수 있지만, 그것이 Railway 운영 배포 완료라는 뜻은 아닙니다.

**`YEBOM_SSO_SECRET`은 현재 인증 경로에 필요하지 않습니다.** 교적부 봉인키 복사·새 난수·개발 사용자로 인증하지 않습니다. 남아 있는 봉인 검사 함수는 격리된 과거 호환 검사 용도입니다. Manus Preview의 다른 도메인에서는 이 공유 쿠키가 자동으로 제공되지 않으며 실제 SSO는 운영 `.yebom.org`에서 확인합니다.

## 로그아웃·계정 전환·이전 경로

같은 화면의 `POST /api/auth/logout`은 중앙 교적부의 이 기기 로그아웃을 중계합니다. 중앙이 발급한 검증된 공유 삭제 쿠키와 재인증 표식만 전달하며 다른 앱의 살아 있는 쿠키를 복사하지 않습니다. 중앙의 `Clear-Site-Data`를 일정에 그대로 적용해 미저장 입력을 지우지 않습니다. 예전 일정의 호스트 전용 로그아웃 표식은 공식 유효 신원이 다시 확인될 때만 정리해 다른 서비스의 재로그인을 막지 않습니다.

계정이 바뀌면 이전 소유자의 초안·설정·인증 전용 상세·변경 이력·휴지통과 미완료 취소/삭제 입력은 새 계정에 표시하거나 새 계정으로 저장하지 않습니다. 미저장 일정 폼은 같은 소유자가 다시 인증되었을 때만 이어 씁니다. 비동기 응답도 요청 당시 계정·권한 범위와 맞는지 확인합니다.

이전 링크의 `/api/auth/sso?next=…`는 안전한 내부 복귀 경로를 쓰는 호환 경로로 남습니다. 새 기본 모달 로그인에서는 이 경로로 화면을 이동하지 않습니다. 기존 콜백에서 인증 실패가 나면 무한 재로그인하지 않고 고정된 안내를 표시합니다.

## 확인 범위

자동 검사는 합성 쿠키·계정·격리 DB와 중계 응답을 사용합니다. 실제 운영 DB에 시험 행사·초안을 넣거나 실제 프로필·비밀번호를 변경하지 않습니다. 코드·격리 검사·실제 빌드·운영 배포·실제 사용자 신원 확인은 서로 다른 결과로 기록합니다. 마지막 운영 반영 상태와 근거는 `docs/VERIFICATION.md`를 참고하세요.

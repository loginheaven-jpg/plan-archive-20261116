## 아직 확인하지 않은 운영 조건

실제 `YEBOM_SSO_SECRET`, 확정 `APP_PUBLIC_ORIGIN`, 최초 `YEBOM_CALENDAR_ADMIN_IDS`가 연결되지 않았다. `.yebom.org` 서비스 도메인·HTTPS·교적부 `from=plan` 복귀 허용 목록과 신뢰 프록시 헤더 정책을 확인해야 한다. 따라서 **실제 운영 사용자 로그인·등록 성공을 주장하지 않는다**. 코드와 테스트에 가상 로그인 우회를 넣지 않았다.

현재는 개발 Preview와 서버 구현 상태다. **운영 공개 배포를 수행하지 않았다**. 외부 Google URL 구독 및 삼성 실제 기기 확인은 고정 운영 주소 공개 후 남아 있다. 재정부 예산 금액 연계 조회와 조직 변경 자동 수집 API도 아직 다음 단계다.

트랜잭션 실패·충돌 자동 검사는 격리 인메모리 쿼리 계약 모델을 사용했다. 별도 격리 MySQL에서 두 연결의 실제 경쟁·장애 주입은 수행하지 않았다. 실제 교회 운영 DB를 이 검사 용도로 변형하지 않았다.

# 연간계획 확장 확인 기록 · 2026-11-15

앞의 2026-11-14 기록은 당시의 상태이며 아래가 이번 수정의 최신 기록이다.

전체 자동 검사 240개가 통과했다. 기존 61개 도메인·44개 서버 검사를 보존하고 계속 반복/기간/순번 요일/날짜 표현/붙여넣기/복사 104개, 초안 권한/원자적 등록/재시도/메타데이터 조회 및 마이그레이션 30개, 공개 순번 요일 정보 보존 1개를 확인했다. 타입·정적 검사 오류 없이 DB 비밀값을 뺀 최종 프로덕션 빌드도 완료했다.

읽기 전용 검토가 발견한 모호한 ‘8시’의 확인 우회, 70개의 큰 초안 목록이 응답 한도를 넘는 문제, 등록된 원본 행사 링크의 무시를 수정했다. 추가로 초기 생성 응답 유실 복구와 반복 상세의 원본 시작 범위를 보완했다. 목록은 본문이 아닌 메타데이터·권한 확인용 조직 배열만 DB에서 조회한다. 격리 검사에서 큰 초안 70개의 목록은 100KB 미만이며 행사 N+1 조회도 하지 않았다.

`tests/annual_ui_regression.py`는 모든 API 요청 19개를 인메모리로 가로채 확인된 연결 오류와 모바일 저장·다음 입력을 검증했다. 반복 설정만 변경해도 오전·오후 확인이 필요한 상태가 보존되고, 20:00을 실제 선택·확인하면 문구가 시간을 덮어쓰지 않는다. 초안 생성 후 응답 유실·수정 재시도 충돌에도 생성 ID로 서버 최신본을 읽고 내 입력을 보존한다. 등록 행 원본 링크가 실제 상세를 열고 현재 회차가 아닌 최초 반복 범위를 표시한다. 모바일의 날짜 미정은 개인 초안 저장 후 다음 행으로 진행하며 행사로 등록하지 않는다. 5개 결과 묶음 통과, 페이지 오류 0, 실제 DB 테스트 쓰기 0이다. 기존 달력의 13개 회귀 결과 묶음도 그대로 통과했다.

기존 0001 마이그레이션의 체크섬과 설정·데이터를 보존하고 0002_annual 초안 테이블만 실제로 추가했다. MySQL JSON 메타데이터 함수는 상수 SELECT로 실제 지원을 확인했다. 개발 건강 경로와 `/annual`은 200, 로그인하지 않은 초안 API는 401이다. 시험을 위해 실제 행사·사용자·장소·초안·감사 레코드를 만들지 않았다.

현재 세 보호된 운영 설정값과 기존 운영 도메인은 연결되어 있다. 실제 교적부와 검증키가 일치하는지, from=plan 복귀 주소가 허용되는지, 사용자 계정으로 실제 로그인·부서 담당 권한과 저장이 작동하는지 및 Google/Samsung 기기 구독의 실제 갱신은 이 자동 검사로 확인했다고 주장하지 않는다. 로그인 우회·가상 운영 계정을 추가하지 않았다. 이번 수정의 공개 배포는 별도 성공 결과와 운영 주소 재확인으로 확정한다.

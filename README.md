# 예봄일정

예봄교회와 열 개 부서의 공동 일정관리 서비스. Next.js 16 · React 19 · TypeScript · Tailwind CSS 4 · MySQL · Drizzle ORM 기반이다. 재정부의 예산 책임 조직 ID를 사용하고 교적부의 실제 SSO 계정을 연동한다.

## 포함 기능

월간·연간·목록 화면, 큰 글씨와 모바일 목록 기본 보기, 왼쪽 전체 선택·부서 필터, 검색, 다가오는 일정과 공개 게시판을 제공한다. 월카드의 빈 영역과 월 이름은 해당 월간으로 이동한다. 두 달력 모두 실제 일정 1개면 바로 상세, 여러 개면 그날 목록, 0개면 편집자만 날짜를 채운 등록창으로 이동한다. 교회력은 행사 건수에 포함하지 않는다.

일정의 주관부서·참여 대상·공개 범위를 구분한다. 입력자·수립일은 서버에서 실제 로그인 사용자와 시각으로 확정하고 최초 기록을 보존한다. 변경자·변경일·이유·변경 전후 기록, 반복과 한 회차 예외, 여러 날 일정, 취소·휴지통·복구, 장소 겹침 안내를 지원한다.

공개 Google Calendar 구독용 ICS 피드와 파일 다운로드를 제공한다. 개인 캘린더 권한을 요구하거나 양방향으로 동기화하지 않는다. 한국 개신교 교회력은 참고 표시이며 교회별 추수감사주일과 선택 관행은 관리자가 설정한다.

## 실행

Node.js 22 이상과 pnpm 11.25.0을 사용한다. 프로젝트의 환경변수는 서버 실행 환경에서 주입한다. 독립 로컬 실행에서는 `.env.example`을 참고하되 실제 비밀값을 Git에 넣지 않는다.

```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
# DATABASE_URL 등 서버 환경변수가 주입된 셸에서 실행
pnpm db:migrate
pnpm dev
```

개발 서버는 0.0.0.0:3000에서 실행한다. 마이그레이션은 한 번의 초기화·업그레이드 작업이며 앱 시작마다 데이터를 초기화하거나 샘플 일정을 등록하지 않는다. 개발·운영 DB를 공유하는 관리 환경에서는 실제 일정에 테스트 데이터를 넣지 않는다.

```sh
pnpm check
pnpm lint
pnpm test
# 개발 서버 실행 후, API 요청을 전부 가로채는 격리 UI 회귀 검사
python3 tests/ui_regression.py
pnpm build
pnpm start
```

UI 검사는 Python Playwright와 Chromium이 필요하며 운영 DB에 이벤트나 가상 사용자를 저장하지 않는다. 테스트용 API 응답은 앱 코드·실제 로그인과 완전히 분리되어 있다.

## 실제 로그인·권한 연결

기존 `saint.yebom.org`의 `saint_record_session` 봉인을 서버에서 검증한다. 필요한 환경변수는 `YEBOM_SSO_SECRET`(기존 교적부의 SESSION_SECRET과 동일, 최소 32자), `APP_PUBLIC_ORIGIN`(확정된 운영 HTTPS 주소), `YEBOM_CALENDAR_ADMIN_IDS`(운영자가 명시 지정한 사용자 ID 목록)이다. 구체적인 절차는 [SSO 연결 문서](docs/SSO_SETUP.md)를 따른다.

SSO 검증키가 없거나 쿠키가 유효하지 않으면 비로그인 상태로 유지한다. `.yebom.org` 밖의 Preview에서는 공유 교적부 쿠키가 자동 전달되지 않는다. 가상 사용자, 기본 비밀번호, 개발 환경 인증 우회는 없다. 재정부의 관리자 역할만으로 일정 관리자 권한을 자동 부여하지 않는다.

첫 관리자가 실제 계정으로 로그인하면 `/settings`에서 교회력·장소를 설정하고 실제 로그인 이력이 있는 사용자에게 조회·부서담당·일정관리 권한을 지정한다. 부서담당자는 허용된 주관부서의 일정만 편집한다. 담당자공개 일정은 주관부서 권한을 기준으로 열람한다.

## 주요 경로

| 경로 | 용도 |
| --- | --- |
| `/` | 교회 일정과 권한에 따른 입력·상세·최근 변경 |
| `/share` | 비로그인 공개 일정 게시판 |
| `/settings` | 교회력·장소·부서 담당 권한 |
| `/api/bootstrap?year=2026` | 해당 연도 일정·다가오는 일정·SSO 상태 |
| `/api/calendar.ics` | 전체 공개 일정의 읽기 전용 구독 |
| `/api/calendar.ics?org=worship,children&all=1` | 선택 부서와 전교회 대상 공개 일정 |
| `/api/calendar.ics?churchYear=1&year=2026` | 교회력 참고 표시를 포함한 공개 피드 |
| `/api/health` | 마이그레이션 준비 완료 여부 |

구글 캘린더에서는 **PC → 다른 캘린더 + → URL로 추가**에 운영 ICS URL을 넣는다. 다운로드한 파일 가져오기는 자동 갱신이 아니다. 구글의 수신 갱신 시각은 이 앱이 통제하지 않는다. 삼성 캘린더는 같은 Google 계정의 구독 캘린더 표시·동기화를 확인한다. 앱·기기별 지원 차이는 실제 기기에서 확인해야 한다.

## 데이터와 소스 보관

일정과 변경 이력은 독립 MySQL DB에 저장하며 예산 금액과 재정 원장은 복제하거나 수정하지 않는다. 모든 애플리케이션 소스·SQL 마이그레이션·운영 문서는 https://github.com/loginheaven-jpg/plan 에 보관한다. 관리 개발 환경의 버전 기록과 이 저장소의 소스 보관은 함께 유지한다.

서버 비밀값, 실제 교인 개인정보, 실제 일정 백업, 비공개 재정부 원본 코드는 이 공개 저장소에 넣지 않는다. 공개 화면과 ICS에는 내부 일정·내부 메모·입력자·변경자 개인정보를 싣지 않는다. 내부 메모는 편집 권한이 있는 담당자에게만 표시한다.
